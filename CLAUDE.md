# myach-bot — футбольный Telegram-бот «Мяч»

Один файл `bot.py`, aiogram 3, работает как **постоянный процесс** на Amvera
(`dp.start_polling(bot)` + фоновый `poll_scheduler()`), не как GitHub Actions
cron — это важно: код не перечитывается на лету, только при реальном
перезапуске/пересборке контейнера.

## Хостинг и деплой — Amvera

- Проект называется `myach-bot` в аккаунте Amvera (владелец аккаунта: djdvkey,
  email djdvkey@gmail.com).
- У этой папки подключён MCP-сервер **`amvera-moscow`**
  (`https://openmcp.msk0.amvera.ru/mcp`, токен в `.mcp.json` — не публиковать,
  не коммитить в git; даёт полный доступ к аккаунту Amvera, не только к этому
  проекту). Через него доступны: `listProjects`, `getProject`, `listFiles`,
  `downloadFiles`, `uploadFiles`, `deleteFiles`, `rebuildProject`,
  `restartProject`, `getBuildLogs`, `getRunLogs`, `getEventLogs`,
  `getCommitHistory`, `scaleProject`, `freezeProject`, `createEnvVars`,
  `listEnvVars`, `createDomain`, `listDomains` и др. — полный список через
  `ToolSearch("amvera")`.
- **Отдельный git-репозиторий Amvera** (`git@git.msk0.amvera.ru:djdvkey/myach-bot`,
  ветка `master`) — это НЕ то же самое, что GitHub-зеркало
  (`github.com/djdvkey-cloud/myach-bot`, ветка `main`). Они не синхронизируются
  автоматически. GitHub-версия используется только как резервная копия кода
  и истории — для реального деплоя работает только репозиторий Amvera.
- Веб-IDE Amvera (`web-ide-*.amvera.io`) и SSH-доступ по ключу — оба
  оказались ненадёжны (то и дело 404 / Permission denied без видимой
  причины). MCP — самый рабочий способ вносить правки в этот проект.
- **Локальная копия и git-история — не источник истины насчёт того, что
  реально выполняется на Amvera.** 15.09.2026 выяснилось: `bot.py` на
  сервере был напрямую отредактирован (добавлены `PLAYER_USERNAMES`/
  `DISPLAY_ALIASES` для `/разделить` и `/добавить`, исправлен fallback-баг)
  в обход git — ни один коммит это не отразил, и локальная копия с
  GitHub-зеркалом разошлись с реальностью на сотни строк. **Правило:**
  перед тем как редактировать `bot.py`, сначала `downloadFiles` (текущий
  файл прямо с Amvera) и сверить с локальной копией — расхождение может
  быть в любой момент, и полагаться на git при этом нельзя.

## КРИТИЧНО: как проверять, что правка реально применилась

13.09.2026 несколько часов ушло на то, что код в репозитории был правильным,
сборка проходила чисто (`exit code: 0`), контейнер стартовал без ошибок — а
бот в реальном Telegram продолжал вести себя по-старому. Причина: в
репозитории залежался устаревший `__pycache__/bot.cpython-311.pyc`
(от более старой версии Python, чем текущий рантайм 3.12), и он
использовался вместо перекомпиляции нового `bot.py`.

**Правило на будущее:** после любой правки в `bot.py` —
1. `listFiles` — убедиться, что `__pycache__` отсутствует в репозитории
   (если появился — удалить через `deleteFiles`);
2. `rebuildProject` (не просто `restartProject` — нужна полная пересборка);
3. `getRunLogs` — проверить отсутствие трейсбеков после свежего старта;
4. и только после этого — **живой тест в реальном Telegram**, не просто
   проверка логов. Логи "всё чисто" сами по себе не гарантируют, что
   исправленный код реально выполняется.

## Модель доступа (кто что может)

`OWNER_ID` (владелец бота) обходит все ограничения и может вызывать любую
команду из любого чата. Для всех остальных:

- `OPEN_COMMANDS = {матч, статистика, составы, отменить, оплата, start, help, id}`
  — доступны рядовым участникам, но **только из общего чата** (`CHAT_ID`),
  не из личных сообщений с ботом.
- `/опрос`, `/переименовать`, `/обнулить` — только владелец, но из любого чата.
- `/добавить`, `/разделить` — только владелец, и **только из личного чата**
  с ботом (жёстче, чем остальные owner-команды).

## Ключевая бизнес-логика

- Очки: гол = 2, пас = 1. Коэффициент = очки / игры.
- `/составы` и `/разделить`: 2 команды при <15 игроков, 3 при ≥15
  (`team_count_for`). Точный перебор до 15 игроков, эвристика — больше.
  Игрок без статистики получает **средний коэффициент известных игроков
  из списка** (`fallback`), а не 0 — эта правка внесена 13.09.2026, до
  этого было 0 (несправедливо занижало команду с новичками).
- `/оплата N`: `GAME_TOTAL_RUB=4500`, округление вверх до 10₽, `+20₽`
  (`BALL_FUND_RUB`) на фонд нового мяча.
- Опрос на игру публикуется автоматически по субботам в 12:00
  (Asia/Yekaterinburg), с вопросом на ближайший понедельник, варианты `+`/`-`.
