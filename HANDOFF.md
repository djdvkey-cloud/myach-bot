   Матч, Статистика, Оплата, Служебные. Тест проверяет, что каждая зарегистрированная команда описана в Help.

   дублируются), при повреждении/неверной структуре `stats.json` изменяющие операции останавливаются,
   файл не перезаписывается, Дмитрию приходит понятное сообщение.
5. **Опрос:** один на субботу; автоматически с 12:00 (Екатеринбург), при возврате бота позже в ту же
   субботу создаётся после запуска; ручной `/опрос` в субботу считается субботним и блокирует
   автоопрос; ручной в другой день субботу не блокирует; повторный `/опрос` в тот же день — только `/опрос да`.
6. **Публикация составов один раз:** после успешной отправки кнопка → «✅ Опубликовано»
   (неактивна); при ошибке отправки кнопка остаётся; после изменения состава — новая
   версия («📢 Опубликовать обновлённый состав»).
7. **Ввод результата кнопками** («⚽ Внести результат матча»): игроки из фактического состава,
   голы/передачи ➖/➕, предпросмотр, «✅ Записать матч» / «✏️ Изменить» / «❌ Отмена».
   `/матч` оставлен как резервный способ.
8. **Фактический состав и замены** («⚙️ Изменить состав», `/состав`): добавить (игрок или гость),
   убрать, заменить — «📌 На его место» или «🔄 Пересобрать команды»; история изменений;
   первоначальный состав сохраняется. Гость без статистики — средний коэффициент игроков (прежнее правило).
9. **Оплата по фактическому составу** («💰 Рассчитать оплату»): N из состава, прежняя формула, предпросмотр,
   отправка в общий чат только по подтверждению и один раз для версии состава. `/оплата N` остался.
10. **Живое оформление:** 11 фраз опроса и 10 финальных фраз составов, ротация без повтора подряд
    (последняя фраза хранится в `/data/ui_meta.json`). Только текст сообщения.
11. При каждом запуске бот присылает Дмитрию «🟢 Мяч запущен»: версия, состояние статистики и игроков,
    состояние меню (счётчики команд по scope, тип кнопки меню до/после).

## 3. Данные в `/data` (Amvera, постоянный том)

| Файл | Назначение |
|---|---|
| `stats.json` | статистика игроков (общая на чат) и последняя игра для `/отменить` |
| `players.json` | игроки: постоянный `pid`, username, Telegram ID, алиасы отображаемых имён |
| `games.json` | журнал состоявшихся игр (№1–4 по датам, далее с составами и голами/передачами игры), раздел 10 |
| `poll_state.json` | текущий опрос и голоса «+» |
| `game.json`, `game_archive.json` | фактический состав текущей игры; прежние игры (последние 20) |
| `guests.json` | гости, добавленные `/добавить` до деления (очищаются после публикации) |
| `ui_meta.json` | последние использованные фразы |
| `last_poll.txt` | маркер «опрос этой субботы создан» |
| `backups/` | копии `stats-*.json`, `players-*.json` (последние 40 каждого) |

## 4. Модель фактического состава (`game.json`)

`teams` — текущий (фактический) состав по командам; `initial` — первоначальный, не меняется;
`rev` — версия состава (растёт с каждым изменением); `history` — кто выбыл / кто добавлен /
кто кого заменил и когда; `ratings`, `guests` — рейтинги и список гостей; `published_rev`,
`payment_rev` — для какой версии уже отправлены составы и оплата; `result`,
`result_recorded` — черновик и признак записанного результата. Новый `/разделить` создаёт
новую игру, прежняя уходит в архив. Фактический состав используется для публикации, ввода
результата и оплаты. Правило коэффициентов — прежнее (`koef_for_names`): статистика игрока,
иначе рейтинг гостя, иначе среднее известных игроков списка. Совпадение имён — без регистра и «ё/е»,
поэтому один человек не раздваивается в статистике.

## 5. Команды и интерфейс владельца (личный чат)

Панель `/menu`; `/help`; `/игроки`, `/игрок добавить|удалить|username …`, `/привязать @user = Имя`;
`/разделить` (`/split`), `/добавить`, `/состав` (`/squad`), `/результат` (`/result`), `/матч`,
`/отменить`, `/статистика`, `/переименовать`, `/обнулить да`, `/оплата` (`/pay`), `/опрос`
(`/poll`, `/опрос да`), `/id`, `/отмена`. Права для игроков не менялись (общий чат:
матч, статистика, составы, отменить, оплата, id, help).

## 6. Порядок работы дальше

- Любое изменение начинать со **свежего клона Amvera `master`**, а не с локальной/GitHub-копии.
- После правки: тесты (`python -m unittest discover -s tests`), push в Amvera, затем живая проверка в Telegram;
  логи без проверки живого сценария приёмкой не считаются. `__pycache__` в репозитории быть не должно.
- **Новая admin-функция → обновить `HELP_SECTIONS` в том же изменении** (тест это проверяет).
- Перед зеркалированием на GitHub не затирать более новые коммиты; не публиковать секреты,
  телефоны и списки username в публичном репозитории.

## 9. Известные ограничения

- Amvera MCP недоступен: логи сборки и запуска недоступны агенту, факт запуска подтверждается
